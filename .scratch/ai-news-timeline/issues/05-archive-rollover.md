# 05 — 归档按月滚动

**What to build:** 窗口恒定在上限条数；被挤出的旧条目滚入**按年月切分**的归档文件，历史不丢失。归档条目与窗口条目结构完全一致（**含中文翻译**）。

**Spec:** `规格-AI新闻订阅-2026-09-15.md` — D11（滑动窗口 + 归档）、D12（窗口未满时向前合并）、D13（按月切分）、D14（归档保留翻译）
**Blocked by:** 03
**Status:** blocked（等待 03）

## 交付的端到端行为

连续运行若干轮之后：窗口文件的条目数恒定在上限；最近被挤出的旧条目出现在对应的**年月归档文件**里；没有任何条目在滚动过程中丢失或重复（窗口与归档的并集 = 历史全集）。若某轮只抓到少量新条目，窗口**用更早的条目向前补足**到上限，而不是只剩当日几条。

页面侧：归档文件在构建期被静态引入，**运行时不发起任何网络请求**。

## 验收

**滚动正确性**
- [ ] 窗口条目数**恒定在上限**；不足时用更早的条目**向前补足**
- [ ] 溢出条目滚入归档，**不重复、不丢失**（窗口 ∪ 归档 = 历史全集，且无交集重复）
- [ ] 重复运行**幂等**：同一天运行两次不产生重复条目
- [ ] 运行顺序打乱（归档已存在、窗口已有内容）时结果仍然正确

**归档结构**
- [ ] 归档**按年月切分**，每个月一个文件（不是按年、不是一条一个文件）
- [ ] 归档条目结构与窗口条目**完全一致**，**包含中文翻译字段**
- [ ] 归档文件在构建期被静态引入；**运行时不发起任何网络请求**
- [ ] 归档文件**不存在**或**为空**时页面仍能构建（空状态兜底）

## 注意

- **归档是存储策略，时间线是呈现策略**——本票只负责前者。使用者是 06。
- **切片粒度是产品决策**（按月），不要改成按年或按条。按月切的理由：单个文件的 diff 更小；而按条切会让文件数线性爆炸（一条一个文件跑十年就撞托管平台的文件数上限）。
- **保留中文翻译**是刻意的：归档的价值就是「以后还能读懂」，删掉翻译等于让它退化成英文链接表。
- **不做历史回填**：归档从本票上线之日起靠时间自然生长，不去爬回旧新闻。
