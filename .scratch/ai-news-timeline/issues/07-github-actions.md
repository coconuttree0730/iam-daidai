# 07 — GitHub Actions 定时任务

**What to build:** 抓取与翻译每天自动运行两次，由机器人身份提交；**无内容变化时不产生提交**；托管侧检测到推送后自动重建站点、页面出现新条目。全流程无需人工干预。

**Spec:** `规格-AI新闻订阅-2026-09-15.md` — D22（失败通知）、D33（cron 用 UTC）、D34（显式写权限）、D35（只有内容变化才提交）、D36（密钥只存 Secret）、D37（定时任务休眠风险）
**Blocked by:** 04、05
**Status:** blocked（等待 04、05）

## 交付的端到端行为

到达定时点时，CI 依次：运行抓取管线（含翻译）→ 有内容变化则以机器人身份提交并推送 → 托管平台检测到推送后重新构建 → 站点出现新条目。若本轮无内容变化，**不产生任何提交**。若抓取失败，**上一次快照保持不变**，并通过平台原生的失败通知被 daidai 发现。

## 验收

**触发**
- [ ] 定时触发以 **UTC** 表达，实际触发时刻与本地预期一致
- [ ] 提供**手动触发入口**（不必等待下一个定时周期就能跑一次）
- [ ] 同一时间点的两次触发不会互相覆盖（并发或串行由调度保证，不产生交错写入）

**提交**
- [ ] **显式声明写入权限**（默认令牌是只读的，不声明会导致推送失败）
- [ ] 提交身份为**机器人**；提交信息带统一前缀与日期
- [ ] **内容无变化时不产生提交**：先判断是否有 diff，无变化直接成功退出
- [ ] 抓取失败**不覆盖上一次成功快照**，且该次运行的最终状态能反映失败

**密钥与安全**
- [ ] 密钥通过**加密机制**注入，**不使用明文变量**（明文变量在有读权限者面前等同公开）
- [ ] **`secrets.*` 不直接插值进 shell 命令**——先落到 `env:`，脚本内读环境变量
- [ ] **不引入任何第三方 action**；如确需引入，锁定**完整提交哈希**而非可变标签
- [ ] 日志中不出现请求头、环境变量、完整错误对象

**可观测与自愈**
- [ ] 连续失败可通过**平台原生的失败通知**被发现（零配置、零额外通道）
- [ ] 定时任务的休眠风险有兜底：该任务每天自行产生提交以自动续期；手动触发入口是备用手段

**端到端验证（本票的最终判据）**
- [ ] 手动触发一次 → 机器人产生提交 → 站点自动重建 → 页面出现新条目
- [ ] 再触发一次（内容不变）→ **不产生新提交**

## 注意

- ⚠️ **端到端验证需要真实推送与真实重建**，这一步在 daidai 检查后、由 daidai 决定何时执行。**不自动 push。**
- **cron 是 UTC**，不要按本地时间写；这是最容易踩的一条。
- **`contents: write` 必须显式声明**，否则推送静默失败。
- **不做多源兜底**：源站不可用时静默保留上一次快照，靠失败通知暴露问题。这是刻意的可用性取舍，不是遗漏。
- 本方案**不需要任何 Cloudflare 侧新增组件**（无 Worker、无 KV、无 Cron Trigger、无 Pages Functions）。托管侧唯一的动作是「检测到 push 后自动重建」。
