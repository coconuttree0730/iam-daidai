# AI 新闻数据 schema —— 页面与脚本两侧的共同契约

- **建立**：2026-09-15（LAB-NEWS 实施期）
- **状态**：**冻结**。改这个文件等于同时改抓取脚本与页面，先改这里再改代码。
- **溯源**：`规格-AI新闻订阅-2026-09-15.md` 的 D6/D7/D8/D9/D10/D13/D14/D24/D31
- **⛔ 硬约束（2026-09-15 站长裁定）**：本管线**不接入任何 LLM**。数据 = 源站原文，
  不翻译、不改写、不生成摘要。`translated` 字段与 GLM 接线（`lib/translate.mjs`、
  `config.translate`、`GLM_API_KEY`）已**整条删除**，04 号票据随之作废。
  理由：LLM 改写并向公众提供会触发《人工智能生成合成内容标识办法》的显式标识义务；
  本站的合规姿势是「原文获取 + 截断摘要 + 标注来源 + 回链原文」，四件事都不需要模型。

## 1. 为什么需要这份文件

数据文件由一条**离线**管线生产（CI 上跑），由**构建期**的页面消费。两侧没有任何
类型共享——脚本是纯 `.mjs`，页面用 `import` 读 JSON。若字段含义只存在于某一侧的
实现里，另一侧就会漂移（改个字段名，页面静默渲染成 `undefined`，而构建依然通过）。
所以字段含义写在这里，两侧都只是它的实现。

## 2. 文件布局

```
src/data/ai-news/
├── current.json            当前窗口，恒定 ≤ windowLimit（30）条
└── archive/
    ├── 2026-09.json        按月切分，文件名 = 该月的 YYYY-MM
    └── 2026-10.json
```

引入方式（两侧都必须遵守）：

| 侧 | 方式 |
|---|---|
| 页面 | `import current from '../../data/ai-news/current.json'` + `import.meta.glob('../../data/ai-news/archive/*.json', { eager: true })` |
| 脚本 | `fs.readFile` / `fs.writeFile`，路径由 `lib/store.mjs` 统一解析，不各写一遍 |

⚠️ **归档必须按 `*.json` glob 引入，不要把月份文件名写死在页面里**——写死等于
每新增一个月就要改一次页面，而归档是自动生长的。

## 3. 文件级结构

### `current.json`

```jsonc
{
  "_comment": "…",                  // 仅供人读，渲染侧忽略（下划线开头 = 不是数据）
  "updated": "2026-09-15T08:12:33.000Z",  // 最近一次成功抓取时间；冷启动 / 从未成功时为 null
  "items": [ /* NewsItem[]，按锚点时间倒序（最新在前），长度 ≤ 30 */ ]
}
```

`updated` 的用途有两处（规格 D10）：页面上的「最后更新」显示、空状态判断。
**它记录的是「成功写出」的时刻，不是「尝试抓取」的时刻**——所以它同时是
「快照的年龄」，比 `Date.now()` 更能反映页面内容的新旧。

### ⚠️ 「入选」与「顺序」是两件事（2026-09-15 两次裁定，别混为一谈）

`items` 有两个独立的问题，契约分别是：

| 问题 | 规则 | 实现位置 | 为什么 |
|---|---|---|---|
| **入选**：哪 30 条进窗口 | **逐源定额**：① 每个源**独立**过「关键词 + 时间窗」→ ② 该源按锚点时间倒序取前 `perSourceLimit`（默认 6，arXiv 4）→ ③ 各源结果合并、按 `id` 去重 → ④ 整体按锚点时间倒序 → ⑤ 截前 `windowLimit`（30）。全程不看热度 | `pipeline.mjs` 步骤 3–6 | 见下 |
| **顺序**：这 30 条怎么排 | 按锚点 `publishedAt ?? fetchedAt` **时间倒序**（最新在前） | `pipeline.mjs` 写盘前 `orderWindow()` | 这是「时间线」语义：从上往下读 = 从新到旧。2026-09-15 站长裁定，**取代**早先「按 score 降序」的写法。 |

**为什么是逐源定额，而不是全局排序**（2026-09-15 换源后的实测依据）：一轮抓取的候选池约
**800 条**（实测 `fetched=804`），而窗口只有 30 个位置。这个池子的形状极不均匀——arXiv
单源一轮贡献 **634 条**，五个中文媒体源合计 **170 条**。若按全局热度或全局时间混排，
arXiv 会把 30 个位置**全部吃光**、中文源一条不进；反过来只看中文源，窗口又会被 IT之家
这类高频源占满（它最新的 6 条落在 **1.3 小时**内）。逐源定额让每个源拿到固定配额，
窗口因此横跨不同**发布节奏**的源：实测 30 条锚点跨度 **23.3 小时**（最旧一条 23.3h 前，
而各源自己的跨度只有 0–20.6h）。这就是「把 30 个位置摊开」在换源之后的等价手段——
旧版靠「热度 × 时间衰减」做同一件事，而 **RSS 没有热度字段**，该手段已不可用。

写盘前 `orderWindow()` 是**顺序契约的唯一实现点**——不要依赖 `lib/archive.mjs` 内部
排序的副产品来定顺序：那里的排序职责是「选出最新的 30 条」（取数），与「输出顺序」
（呈现）是两回事，职责混同会让顺序契约在 rollover 被调整时静默失效。

`perSourceLimit` 是**配额**，不是「上限兜底」：它同时承担「防单源淹没」与「保源多样性」
两件事，改它等于改窗口的源构成。`windowLimit` 只在各源配额之和超过它时才起作用。

### `archive/YYYY-MM.json`

```jsonc
{
  "_comment": "…",
  "month": "2026-09",   // 与文件名一致
  "items": [ /* NewsItem[]，与 current.json 完全同构（规格 D14） */ ]
}
```

归档文件**不带 `updated`**：它不是一个时间点快照，而是一个按月累积的桶。
`month` 字段是冗余的（文件名已有），保留它是为了让**单条 item 被取出后仍能
知道自己的归属月**，调试与未来做分页时有用。

## 4. NewsItem（唯一需要逐字段记住的部分）

```jsonc
{
  "id": "3f9a1c07d2b4",          // string，12 位十六进制
  "url": "https://www.ithome.com/0/000/000.htm",  // string，绝对 URL
  "source": "IT之家",             // string，来源标签（界面直接显示）
  "lang": "zh",                  // 'zh' | 'en'：原文语言（页面语言门控的唯一依据，见 §6）
  "title":   { "en": "…", "zh": "…" },        // LocalizedText（两槽同放原文，见 §4）
  "summary": { "en": "…", "zh": "…" },        // LocalizedText，en 可以为空串
  "publishedAt": "2026-09-15T06:00:00.000Z",  // string | null
  "fetchedAt":   "2026-09-15T08:12:33.000Z"   // string，必有
}
```

### 逐字段

| 字段 | 类型 | 语义与约束 |
|---|---|---|
| `id` | `string` | **去重主键**。= `sha256(规范化 URL)` 的前 12 位十六进制（D9）。规范化口径见 §7。同一篇文章的不同追踪参数形式**必须**得到同一个 `id`。 |
| `url` | `string` | 条目外链，**原样未规范化**（追踪参数保留）——它是给读者点的，不是给程序比的。页面渲染时补 `target="_blank"` / `rel="nofollow noopener noreferrer"`（D26）。 |
| `source` | `string` | 来源标签，如 `"IT之家"` / `"arXiv cs.AI"`。取自 `config.mjs` 白名单里该源的 `label`（不取源站自称的名字，避免改版后界面文字漂移）。用于界面上标注来源（用户故事 9）。 |
| `lang` | `'zh' \| 'en'` | **原文语言**。取自源白名单里该源的 `lang`（见 `config.mjs`）。页面靠它判断「这条到底是中文内容还是英文内容」（§6），**不要**试图从 `title` 猜语言。 |
| `title.en` | `string` | 英文标题位。**必有、非空**——一条没有标题的新闻没有存在意义，解析阶段就应丢弃。⚠️ 单语源（当前全部 6 个源都是）下它是**原文字符串本身**，中文源时它是中文。 |
| `title.zh` | `string` | 中文标题位。**必有、非空**：未翻译时它**等于 `title.en`**，而不是 `""`（D7）。 |
| `summary.en` | `string` | 英文摘要位。**可以为空串**：源站的条目类型本身可能就没有正文（或摘要短过 `minSummaryChars`，被 `shape.mjs` 主动置空以滤掉「点击查看原文>」这类导流语）。这不是错误状态。 |
| `summary.zh` | `string` | 中文摘要位。未翻译时等于 `summary.en`（含「两者都是空串」的情况）。**一律截断到 `summaryMaxChars`（140）**——这是版权安全边界，不是排版选择（见 §8 第 3 条）。 |
| `translated` | `boolean` | `true` = 本条的中文字段**确实经过翻译**。`false` = 中文字段只是英文字段的副本。**页面不靠它单独判「未翻译」**（§6）：单语 RSS 源下所有条目都是 `false`，按单值判会把中文源的条目全部误标成「未翻译」。 |
| `publishedAt` | `string \| null` | 原文发布时间（ISO 8601 UTC）。**可以缺**：部分源的条目没有发布时间。 |
| `fetchedAt` | `string` | 抓取时间（ISO 8601 UTC）。**必有**。 |

### 已删除字段：`heat`

旧版（数据源 = Hacker News）有一条 `heat`（`points + num_comments`）。**换源后该字段已被
删除，不要加回来**：RSS 没有热度信号，而「入选」也不再依赖它（§3 已改为逐源定额）。
消费者（四个页面 + `ai-news-timeline.js`）从未读取过它——删除它不构成破坏性变更。

### `LocalizedText` = `{ zh: string, en: string }`

**为什么是嵌套对象而不是 `titleEn` / `titleZh` 两个平铺字段**（D6）：项目已有一个
数据层双语的既有约定 `pickLocalized()`（`src/i18n/utils.ts`），它识别「同时含
`zh` 与 `en` 两个键的对象」。沿用同一形状，页面就能直接 `pickLocalized(item.title, locale)`
取当前语言，不需要为新闻数据单写一套分支。

⚠️ 反过来说：**不要**给 NewsItem 顶层加 `zh` / `en` 键——那会让整个 item 被
`pickLocalized` 误判为一个双语袋子，取出来的是半个对象。

## 5. 时间线定位字段（页面必读）

```
anchor(item) = item.publishedAt ?? item.fetchedAt
```

**页面不得假设 `publishedAt` 存在，也不得假设两个字段格式统一**（D8）。
渲染时间统一走 `new Date(anchor(item))` + `Intl.DateTimeFormat`，并在
`Number.isNaN(d.getTime())` 时**回退到 `fetchedAt`**——这一条是「渲染永不崩」的底线。
分组（年 / **日**）也一律基于 `anchor()`，不是 `publishedAt`。

⚠️ **显示与切日都用 `Asia/Shanghai`，不用 UTC**（2026-09-15 修正，见规格 D43）。
用 UTC 会把 `17:47(+08:00)` 发布的国内新闻显示成 `09:47`，并把 `+08:00` 深夜的条目
切到第二天——「按日期分组」直接错一天。**分组键与显示格式必须走同一个时区**：
实现用 `en-CA` 的 ISO 形状短日期取「时区内的日键」，避免手算偏移。
分组粒度是「日」不是「月」：窗口 72h、冷启动实测跨度 23.3h，按月分组恒为 1 组。

## 6. 语言门控（页面侧契约）

**背景**：`{en, zh}` 这两个语言袋子在**单语源**下是同一串内容（`shape.mjs` 按 D7 把
未翻译的字段填成副本）。因此页面**不能**无条件地「中文页渲染两组、英文页渲染 `en` 组」——
那样中文页会把每句标题印两遍（主位一次、对照层一次），英文页会把中文标题当英文渲染。
判据只有一个：**`lang`**（§4）。

### 6.1 中文页 `/lab/news/`

| 元素 | 渲染条件 | 为什么 |
|---|---|---|
| 主标题 / 主摘要 | 恒渲染 `title.zh` / `summary.zh` | D7 保证这两个字段**非空**，取到的永远是「能读的那一份」（中文源 = 原文，英文源未翻译 = 英文原文） |
| 英文原文对照层 | **仅当 `title.en !== title.zh`** | 两值相同 ⇔ 不存在第二种语言。无条件渲染 = 同一句印两遍 |
| 「未翻译」标 | **仅当 `lang !== 'zh'`** | 中文源本来就是中文，不是「翻译缺位」；`translated` 字段已删（§4），`lang` 是唯一判据。用 `lang !== 'zh'` 而非 `lang === 'en'` 取反，是为了让缺 `lang` 的旧数据也判对 |

### 6.2 英文页 `/en/lab/news/`

**只收 `lang === 'en'` 的条目，其余跳过不渲染。** 这是 ticket 02 验收条款
「页面内不出现任何中文字段」的直接落地（2026-09-15 站长裁定，三个备选中选此：
另两个是「照常显示 + 标注原文语言」——要改写验收条款，「开 zh→en 翻译补齐英文标题」
——要引入密钥与第三条数据流，与「稳定 > 安全 > 合规 > 质量」的优先级相悖）。

- ⚠️ 这是**隐藏不是删除**：中文原文在中文页完整可见，数据层的两个语言袋子都还在。
- 本页**不渲染**「未翻译」标：门控后此处只可能有原文为英文的条目，该标对英文读者零信息。
- **已知并接受的代价**：英文侧时间线显著比中文侧稀（窗口内通常只有 arXiv 几条），
  且两页条目集合**不再相同**。
- **空态必须分两种成因**（否则与紧随其后的「最后更新 {time}」自相矛盾）：
  数据一条没有 → `news.emptyNote`；有数据但全被门控滤掉 → `news.emptyEnOnly`。

### 6.3 新增数据源时

`config.mjs` 的 `sources[].lang` **决定这个源出现在哪些页面上**。想要两页都显示，
源必须是双语源（同一篇同时提供两种语言）——当前白名单里**没有**这样的源，于是
中文源的条目只出现在中文页。这是刻意的，不是遗漏。

## 7. URL 规范化口径（去重主键的唯一来源）

规范化是**纯函数**，输入输出都是字符串，实现见 `lib/url.mjs`：

1. 解析失败 → 原样返回（不抛错；主键仍能算出来，只是去重能力退化）
2. 去掉 fragment（`#…`）
3. 去掉查询参数里的追踪项（`utm_*`、`fbclid`、`gclid`、`ref`、`ref_src`、`source`、`mc_cid`、`mc_eid`…）
4. 其余查询参数**按 key 排序后重新拼接**（顺序不同不应产生两条）
5. host 统一小写；去掉默认端口（`:80` / `:443`）
6. 去掉末尾 `/`（根路径 `/` 保留）
7. 去掉 `www.` 前缀

✅ `https://a.com/x?utm_source=h&utm_medium=t` ≡ `https://a.com/x/`
✅ `https://A.com:443/x#frag` ≡ `https://a.com/x`
❌ `https://a.com/x?id=1` ≢ `https://a.com/x?id=2`（业务参数不同 = 不同页面）

## 8. 抓取脚本必须遵守的四条硬规则

1. **失败时什么都不写。** 抓取结果少于 `minItems`（默认 5）时，脚本**不打开文件**、
   **以成功状态退出**（D18）。工作流靠这一点保持「上一次快照」——
   ⚠️ 退出码为 0 是刻意的：静默失败由 CI 的通知机制兜底，而不是靠弄红构建。
   注意「不写文件」是**字面意思**：不要写一个空的 `items: []` 覆盖旧快照。
2. **降级不产生空字段。** 见 §4 的 `title.zh` / `summary.zh` 两行（两个语言槽同值，不做翻译）。
3. **摘要一律截断到 `summaryMaxChars`（140 字符）。** 这是**版权安全边界**，不是排版选择：
   源站 `description` 的长度谱极宽——实测从 16 字的导流语到 **35,283 字**的整篇正文都有。
   存整篇 = 把外站受版权保护的正文搬进本仓库并随站点分发，与「不入库全文」的既有裁定冲突。
   截断后**不补省略号**：保持它是原文的忠实前缀，不掺入我们自己的字符。
4. **内容与上轮完全一致时整条不写盘**（2026-09-15 修，D35 与 D37 的交点）。
   判据 = 「将要落盘的 `items` 序列化后与上轮 `current.json` 的 `items` 逐字节相同」，
   一致则不写、保留旧 `updated`（其语义因此是「**内容最后变化的时刻**」，不是「最后抓取时刻」）。

   ⚠️ 这一条以前是**隐性失效**的：每个成功分支都无条件写 `updated: nowIso`，
   顶层字段一变，workflow 的 `git diff --cached --quiet` 就恒为非真、
   「无变化不提交」的分支永远走不到。实测证据在 `qa/ai-news-pipeline.test.mjs` 第 18/23 项。

   但**不能**因此把写盘节流做成无条件：D37 记录「仓库连续 60 天无活动，GitHub 会停用
   定时任务」，缓解手段正是「让任务自己产生提交来续期」。所以保留兜底
   `forceWriteAfterDays`（45 天）：距上次写盘超过它时，即使内容没变也强制写一次。

   走这条路径时管线返回 `status: 'unchanged'`（**不是** `'skipped'`）：
   `skipped` 只表示「本次不写是因为数据不足/全源失败」，而 `unchanged` 是成功结果。
