# 用 Cloudflare 从零搭一个个人网站

> 这份教程面向**完全没搭过网站的人**。每一步都写清楚"点哪里、填什么、为什么"。下面所有步骤都是我这个站（`iam.daidai.click`）真实走过的路径，包括**我做错的那几次**——踩坑部分比顺利部分值钱。

## 开工前，先确认你手上有这些

不用怕，就三样：

| 你需要         | 说明                       | 怎么弄                           |
| ----------- | ------------------------ | ----------------------------- |
| **一台电脑**    | Windows / Mac / Linux 都行 | 你正在用的这台                       |
| **Node.js** | 一个让电脑能跑网站代码的程序           | 去 `nodejs.org` 下载 LTS 版，一路下一步 |
| **Git**     | 一个管代码版本的工具               | 去 `git-scm.com` 下载安装          |

再装个**邮箱**能用的（要用来注册账号）。

然后打开电脑的**终端**——

- Windows：开始菜单搜 `PowerShell`
- Mac：聚焦搜索（⌘ + 空格）搜 `Terminal`

**终端是干什么的**：它是一个"打字指挥电脑"的窗口。本教程里所有灰底代码块，都是让你**复制粘贴进去、然后按回车**的。不用理解每个字母的意思，照着做就行。

装好之后，在终端里敲这两行验证（能显示出版本号就成功了）：

```bash
node -v      # 应该显示 v20.x 或更高
git --version
```

> 💡 **所有命令都是复制粘贴 + 回车**。遇到看不懂的英文报错，先别慌——本文第 6 节专门讲常见报错。

## 0. 为什么选 Cloudflare 当"房东"

先说清楚这个概念，后面就顺了。

**搭网站需要两样东西**：一块地（放你的网页文件）和一个门牌号（域名，别人才能找到你）。

传统做法要找两家公司：一家买域名（比如阿里云、GoDaddy），一家买服务器放文件。**Cloudflare 把这两件事合在一家做，而且核心部分免费。**

个人网站的托管选择主要就三家：Cloudflare、Vercel、Netlify。我选 Cloudflare 的理由：

| 你关心什么         | Cloudflare 的情况                                         |
| ------------- | ------------------------------------------------------ |
| **要花多少钱**     | 免费够用。免费额度：每月 500 次构建、单站 2 万个文件、单文件最大 25 MiB。个人站基本碰不到上限 |
| **流量大了会不会收费** | **不会**。静态文件的访问请求不计费、不限量——这是它区别于其他家最实质的一点               |
| **域名贵不贵**     | 域名按**成本价**卖，不加价。所以不会有"首年 10 元、续费 300 元"那种陷阱            |
| **要开几个账号**    | 一个。邮件、统计、边缘计算全在同一个后台                                   |

网上叫它"赛博大善人"就是这个意思：**本来要开四五个账号的事，它收在一个免费面板里做完了。**

**它不适合什么**（也说清楚，免得你走冤枉路）：

- 需要**常驻程序**、连数据库、长连接的动态网站 → 这种要租 VPS（一台你自己管理的服务器），Cloudflare 不是最优选
- **构建超过 20 分钟**的大型项目 → 免费套餐有超时限制
- 重度依赖某些**系统级程序库**的项目 → 它的服务器环境和普通服务器不一样

我这种"纯静态"的个人站（网页就是一堆 HTML 文件，不需要后台程序）完美匹配。

## 1. 第一步：注册账号 + 买域名

> **这一节你要完成**：有一个 Cloudflare 账号，有一个属于你的域名。

### 1.1 注册账号

1. 浏览器打开 `dash.cloudflare.com`
2. 用邮箱注册（免费套餐 Free 就够全程用，不用付钱）
3. **强烈建议开两步验证**：右上角头像 → My Profile → Authentication → 开启

为什么要开：你的账号里有域名的管理权限，等于家里的钥匙。被盗走的损失比普通账号大得多。

### 1.2 买域名

1. 左侧菜单找 **Domain Registration**（域名注册）→ **Register Domains**
2. 搜索你想要的域名，比如 `你的名字.com`

**挑选建议**：

- **优先 `.com`**，其次 `.dev` / `.click` / `.me`。避开那些"首年超便宜"的小众后缀
- **建议一次买 3–5 年**。Cloudflare 支持直接买 1–10 年，一次买够省得每年惦记
- 买完域名**自动就生效了**——不需要你做任何 DNS 配置（这就是在 Cloudflare 买域名的省事之处）

> **已有域名在别家（阿里云、GoDaddy 等）？** 不用迁注册商，只要把"解析权"交给 Cloudflare：  
> Dashboard → **Add a site** → 输入你的域名 → 选 Free 套餐 → 它会给你两个**名称服务器地址**（形如 `xxx.ns.cloudflare.com`），去原注册商后台把这俩填进去替换掉原来的。等生效（几分钟到 48 小时不等），Cloudflare 就接管了。
>
> 「名称服务器」是什么：可以理解成"电话总机"。全世界的网络要访问你的域名时，先问这个总机"该转到哪台机器"。

### 1.3 你会得到什么

买完域名后，你的账号里这个域名（Cloudflare 叫它 **Zone**，你就理解成"这个域名的控制台"）下会有：

- **DNS 管理** —— 记录已自动配好，不用管（DNS 就是"把域名翻译成服务器地址"的电话簿）
- **SSL/TLS** —— 自动给你配好 HTTPS 证书，还会自动续期（不用手动搞，这点很省心）
- **Email Routing** —— 免费邮件转发（第 5 节会用到）
- **Workers & Pages** —— 放网站文件的地方（第 4 节的主角）
- **Analytics** —— 免费的访问量统计，不收集用户隐私

## 2. 第二步：在电脑上把网站做出来

> **这一节你要完成**：电脑上有一个能跑起来的网站，命令一敲就能在浏览器看到。

托管平台是后面的事，**先让网站在你本地活着**。

### 2.1 选个"建站工具"

我从零写网站用的工具叫 **Astro**。它不是唯一选择，但对我这种需求很合适：

- **默认轻快**：生成的网页就是纯 HTML，不会塞一堆用不上的代码
- **写错会报错**：文章头部信息填错格式，它会直接告诉你哪里错了，不会悄悄产出一个坏页面
- **不被绑架**：它生成的就是普通网页文件，哪天想换平台，文件照搬就行

**小白最省事的做法是跟着敲一遍**（不用懂原理）：

```bash
npm create astro@latest my-site
```

它会问你几个问题，**一路按回车选默认值**就行。然后：

```bash
cd my-site        # 进入刚创建的项目文件夹
npm install       # 安装依赖（第一次要等一两分钟）
npm run dev       # 启动本地预览
```

终端会显示一个网址，通常是 `http://localhost:4321`。**在浏览器打开它，你会看到网站的样子。**

> 「依赖」是什么：你的网站要用到别人写好的工具包，`npm install` 就是把这些工具包下载到本地。

**恭喜，你的第一个网站已经存在了。** 按 `Ctrl + C` 可以停掉预览。

### 2.2 改一个关键设置

打开项目根目录的 `astro.config.mjs`——这是网站的"总配置文件"。

找到 `site` 这一项，**改成你最终要用的网址**：

```js
export default defineConfig({
  site: 'https://iam.daidai.click',   // ← 改成你自己的域名
  output: 'static',
  // ...
});
```

**为什么必须改**：这个值决定了搜索引擎收录你时用的网址、以及分享到微信/微博时显示的链接。**写错了后面发现要返工。**

顺便解释 `output: 'static'`——它表示"我的网站全是静态文件，不需要后台程序"。个人博客、作品集基本都是这个模式。**如果你的站确实需要后台，才去装额外的适配器；不需要就别装**，装了反而多一堆麻烦。

### 2.3 确认能打包

```bash
npm run build
```

这一步叫"**构建**"——把源码加工成最终能上线的文件（都放进 `dist` 文件夹）。看到成功提示就对了。

**这一步的意义**：先确认"零件在你的电脑上是好的"。万一以后上线时云端报错，你至少知道问题出在云端环境，而不是你的代码。

## 3. 第三步：把代码上传到 GitHub

> **这一节你要完成**：代码在 GitHub 上有一份，云端能拉到。

Cloudflare 的自动部署是"从 GitHub 拉你的代码 → 自动构建 → 上线"。所以先把代码传上去。

### 3.1 上传

1. 打开 `github.com`，注册账号
2. 右上角 **+** → **New repository**，起个名字（比如 `my-site`）
3. **要点：这里选 `Private`（私有）** —— 原因见下
4. 创建后跟着页面提示把本地代码推上去（GitHub 会给现成命令），大致是：

```bash
git init
git add .
git commit -m "第一次提交"
git branch -M main
git remote add origin <GitHub 给你的地址>
git push -u origin main
```

### 3.2 ⚠️ 一个必须知道的红线：放进 Git 的东西删不干净

**这是我最贵的一课。**

我曾经把**真实邮箱地址**写进了仓库文件。发现之后我改掉了那个文件——但**没用**。旧的提交记录里还留着，任何人把仓库下载下来都能翻出来。最后只能重写整个历史记录才清掉。

**所以：**

- **密码、邮箱、密钥、内部地址，一律不要写进代码文件**
- 需要用到这些值的时候，用"环境变量"或平台提供的"密钥存储"功能（第 5 节会演示）
- **新建仓库默认选 Private**，除非你有明确理由要公开
- 万一不小心提交了：**改文件不够**，必须重写历史——越早发现越好处理

> 「Git 提交记录」是什么：Git 会保存每一次修改的快照，像游戏的存档。你删掉当前文件，旧存档里那份还在。

## 4. 第四步：让 Cloudflare 自动部署（核心）

> **这一节你要完成**：每次改完代码一提交，网站自动更新。这是全篇最关键的一节。

Cloudflare 有**两条**托管路线，长得像但不一样，**别选错**：

|          | 经典 Pages                         | **Workers**（本文用的）                      |
| -------- | -------------------------------- | -------------------------------------- |
| 入口位置     | Workers & Pages → Create → Pages | Workers & Pages → Create → **Workers** |
| 静态文件设置在哪 | 在网页后台填                           | 在**你仓库里的配置文件**声明                       |
| 现在官方态度   | 老路线，仍在维护                         | ✅ **当前主推**，新建项目建议走这条                   |

**新建项目直接选 Workers。**

![两条路看着一模一样，只有一条走得通](/blog/cloudflare-personal-site-guide/03-two-paths.webp)

### 4.1 先在仓库里建一个配置文件

在项目**根目录**新建一个文件，名字叫 `wrangler.jsonc`，内容：

```jsonc
{
  "name": "my-site",
  "compatibility_date": "2026-09-01",
  "assets": {
    "directory": "./dist",
    "not_found_handling": "404-page"
  }
}
```

每一项是什么意思：

| 字段                   | 填什么         | 说明                                       |
| -------------------- | ----------- | ---------------------------------------- |
| `name`               | 自定义名字       | 这个部署任务的名字，只影响后台显示                        |
| `compatibility_date` | **一个过去的日期** | 告诉 Cloudflare 用哪个版本的环境。**不要写未来日期**，会部署失败 |
| `directory`          | `./dist`    | 你的网站文件在哪。`dist` 是第 2 步构建产物的文件夹，**别改**    |
| `not_found_handling` | `404-page`  | 访客访问不存在的页面时，显示你自定义的 404 页，而不是干巴巴的报错      |

#### ⚠️ 踩坑 1：少了这个文件，部署会失败

**如果仓库根目录没有 `wrangler.jsonc`**，Cloudflare 会自动"猜"你的项目类型，猜错方向后给部署链引入一个不兼容的模块，报错：

```
UNLOADABLE_DEPENDENCY
```

**记这一句就够**：这个文件不是可选的，**必须手写、必须放根目录**。

**想知道具体原因？（进阶，不看也不影响操作）**

没有配置文件时，部署工具会触发 auto-config：它检测到 Astro 项目，自动执行 `astro add cloudflare`（添加 Cloudflare 适配器）并**二次构建**。而我的项目用了 `@resvg/resvg-js` 做分享图渲染，它包含**原生二进制模块**（`.node` 文件），部署环境无法打包这类模块。

关键点是：配置文件的**存在本身**就会抑制 auto-config。所以要显式声明，别让工具猜。


### 4.2 在网页后台接入 GitHub

1. Cloudflare 后台 → **Workers & Pages** → **Create** → **Workers** → **Connect to Git**
2. 授权它读取你的 GitHub，选中你的仓库
3. 填入下面三行（**照抄**）：

| 填什么                  | 填什么值                           |
| -------------------- | ------------------------------ |
| Build command（构建命令）  | `npm run build`                |
| Deploy command（部署命令） | `npx wrangler deploy`          |
| Version command      | `npx wrangler versions upload` |

Root directory 保持 `/`（如果你的项目就在仓库根目录）。

#### ⚠️ 踩坑 2：这里的"构建命令"是写死的，改 `package.json` 没用

我一开始想让构建时额外做一件后处理工作，就去改了 `package.json`：

```json
// ❌ 这样做线上一动不动
"build": "astro build && 额外的处理命令"
```

本地好得很，**线上完全没执行后半截**。

**原因**：Cloudflare 只执行你在后台填的那一行字（`npm run build`）。它**不会**去读你的 `package.json` 看里面还有没有别的命令。

**记这一句**：后台填什么，线上就只跑什么。**想在构建后加动作，要挂在项目自己的构建流程里，而不是改 npm 脚本。**

![墙里只接走纸条的前半截，后半截卡在墙外](/blog/cloudflare-personal-site-guide/04-only-half-command.webp)

**正确做法（进阶，暂时看不懂可以直接跳过，不影响你上线）：**

把后处理挂到 Astro 的构建生命周期钩子上：

```js
// astro.config.mjs
import { spawnSync } from 'node:child_process';
import { fileURLToPath } from 'node:url';

function pagefindIndexer() {
  return {
    name: 'pagefind-indexer',
    hooks: {
      'astro:build:done': ({ dir, logger }) => {
        const outDir = typeof dir === 'string' ? dir : fileURLToPath(dir);
        // --no-install：只允许本地已安装的包，防止 npx 静默从网上下载
        const res = spawnSync(
          'npx',
          ['--no-install', 'pagefind', '--site', outDir],
          { stdio: 'inherit', shell: true },
        );
        if (res.status !== 0) {
          throw new Error(`索引生成失败（退出码 ${res.status}）`);
        }
        logger.info('索引已生成');
      },
    },
  };
}

export default defineConfig({
  integrations: [pagefindIndexer()],
});
```

这样不管云端跑的是 `astro build` 还是 `npm run build`，钩子都会触发。**原则：把后处理绑在框架的构建流程上，而不是绑在平台的后台配置上。**

顺带一句：自动化构建环境里跑 `npx` 养成加 `--no-install` 的习惯——不加的话它找不到包会**静默从网上下载**，可能拉到你没预期的版本。

### 4.3 首次部署

点 **Save and Deploy**。云端会自动跑一遍：下载依赖 → 构建 → 部署。

成功后你会拿到一个临时网址（形如 `xxx.workers.dev`）。**先打开它，确认网站正常**，再往下做。

### 4.4 绑定你自己的域名

现在临时网址能用，但你要的是自己的域名。

后台 → 你的 Worker → **Settings** → **Domains & Routes** → **Add** → **Custom Domain** → 填你的域名（比如 `www.你的域名.com` 或 `blog.你的域名.com`）。

Cloudflare 会自动建好解析记录、签发 HTTPS 证书、把访问导过来。**等几分钟刷新看看。**

> **这里要做一个决定，而且会影响后面**：用**主域名**（`你的域名.com`，术语叫 apex）还是**子域名**（`blog.你的域名.com`）？
>
> 我用的是子域名 `iam.daidai.click`。**记住你选了哪个** —— 第 5 节的坑 4 就是因为记混了这个。

## 5. 第五步：加一个联系表单（不用第三方服务）

> **这一节你要完成**：访客能在你网站上填表给你发消息，而你的真实邮箱不会暴露。

站上线了，但访客联系不到你。常见做法是接第三方表单服务（Formspree、EmailJS 之类），要注册、要密钥、有免费额度。

**Cloudflare 可以原生做完这件事，不用第三方。**

流程是这样的：

```
访客填表 → 你的网站收到 → Cloudflare 的"小程序"处理 → 发邮件到你的邮箱
```

那个"小程序"叫 **Worker**——可以理解成**跑在 Cloudflare 服务器上的一小段代码**，专门负责收表单、发邮件。


### 5.1 建这个"小程序"

在项目里新建一个 `worker` 文件夹，里面放两个文件。

**文件一**：`worker/wrangler.jsonc`

```jsonc
{
  "name": "my-site-contact",
  "main": "src/index.js",
  "compatibility_date": "2026-08-15",
  "routes": [
    { "pattern": "你的域名.com/api/*", "zone_name": "你的域名.com" }
  ],
  "send_email": [
    { "name": "EMAIL" }
  ],
  "vars": {
    "FROM_EMAIL": "no-reply@你的域名.com",
    "SUBJECT": "来自网站的联系",
    "ALLOWED_ORIGINS": "https://你的域名.com"
  }
}
```

几个关键点：

| 配置                | 作用                                                      |
| ----------------- | ------------------------------------------------------- |
| `routes`          | 告诉 Cloudflare："凡是访问 `/api/` 开头的请求，交给这个小程序处理"，而不是去静态文件里找 |
| `send_email`      | 这是 Cloudflare **自带的发邮件能力**，不需要第三方服务、不需要申请密钥             |
| `ALLOWED_ORIGINS` | 只接受来自你自己网站的提交，挡掉一部分自动脚本                                 |
| `FROM_EMAIL`      | 邮件从哪个地址发出（用你域名下的地址才不会被当垃圾邮件）                            |

**⚠️ 收件邮箱不要写在这个文件里。** 这个文件会进 Git 仓库（第 3.2 节讲过的红线），要用"密钥存储"功能单独存：

```bash
npx wrangler secret put TO_EMAIL
# 然后按提示粘贴你的真实邮箱
```

**文件二**：`worker/src/index.js` —— 处理表单的具体代码（告诉它"收到表单后做什么"）。

**这一步需要写一点 JavaScript 代码**，本文不展开具体实现，你要做的事分三层：

1. **判断请求来自哪里** —— 是不是从你自己的网站提交的
2. **判断是不是机器人** —— 常见的做法是在表单里藏一个访客看不见的字段，正常人手填时不会碰它，机器人会无脑填满
3. **调用发邮件能力** —— 把表单内容发到你的邮箱

如果你完全不会写代码，**这一节可以整节跳过** —— 前面五步做完，网站已经完整可用了；表单是加分项，随时可以回头补。

### 5.2 开启发信和收信（这两件事是分开的）

**这一点我一开始没分清，折腾了不少时间。**

**发信（你的网站发邮件给你）** 需要先"激活"你的域名的邮件功能：

```bash
npx wrangler email sending enable 你的域名.com
```

> ⚠️ **这条命令会报错**：`Unauthorized [code: 2036]`
>
> **不是你的问题，也不是重登能解决的**——命令行的登录凭证**天生没有改 DNS 的权限**，而这个操作需要改 DNS。**必须去网页后台点**：  
> Email Service → Email Sending → Onboard Domain → 选你的域名。
>
> 激活后 Cloudflare 会自动配好 SPF / DKIM / DMARC（邮件防伪和防垃圾的三项标准配置），**这是你发的邮件不进垃圾箱的保障**。

![一整串钥匙，没有一把能整把插进这个锁孔](/blog/cloudflare-personal-site-guide/05-wrong-key.webp)

> **费用边界**（我核实过）：
>
> - 发到**你自己账号里验证过的邮箱** → **所有套餐都免费**
> - 发到**任意邮箱**（比如访客填的地址）→ 需要付费套餐（$5/月）
>
> 我的表单只发给自己，所以停在免费档。

**收信（别人发到 `hello@你的域名.com` 能收到）** 用 Email Routing：

后台 → 你的域名 → **Email** → **Email Routing** → 启用 → 添加规则：

```
hello@你的域名.com  →  你的真实收件邮箱
```

你的真实邮箱会收到一封确认邮件，点一下确认就生效。

**好处**：网页上只显示 `hello@你的域名.com`，**你的真实邮箱永远不暴露**（也不怕被爬虫抓去发垃圾邮件）。

### 5.3 部署 ＋ 一个 404 的坑

```bash
cd worker && npx wrangler deploy
```

#### ⚠️ 踩坑 4：网址写错了，表单就 404

我最开始只填了**主域名**，但我的网站实际跑在**子域名**上：

```jsonc
// ❌ 只配了主域名
"routes": [{ "pattern": "daidai.click/api/*", "zone_name": "daidai.click" }]
```

**现象**：表单提交，404。

**原因**：Cloudflare 的规则是**严格匹配**的。`daidai.click` 和 `iam.daidai.click` 在它眼里是**两个完全不同的地址**，前者的规则不会管后者。

**修复**：把你实际在用的地址写对（两个都写也行）：

```jsonc
"routes": [
  { "pattern": "iam.daidai.click/api/*", "zone_name": "daidai.click" },
  { "pattern": "daidai.click/api/*", "zone_name": "daidai.click" }
]
```

**记这一句**：配置任何"网址相关"的东西时，**你网站上地址栏里实际显示的是什么，就填什么**。主域名和子域名是两回事，别想当然。

#### ⚠️ 踩坑 5：改了这个小程序，不会自动上线

这是最容易忘的一点：

| 你改了什么            | 怎么让它上线                          |
| ---------------- | ------------------------------- |
| 网页内容、样式          | `git push` → **自动部署**           |
| `worker/` 里的表单程序 | **必须手动**跑 `npx wrangler deploy` |

**记住**：表单程序不在自动部署的范围里。改完一定要手动推一次。

### 5.4 防垃圾提交的实话

- 上面那些防护（来源校验、蜜罐字段、提交速度检查）挡的是**无差别扫描脚本**，**挡不住铁了心的人**
- 真正的保险在于：收件地址写死在密钥里，**最坏情况也只是给自己发垃圾邮件**
- 真被刷了再加 **Cloudflare Turnstile**（免费的人机验证），改动集中在一个文件里

## 6. 上线后你可能遇到的三个问题

这三条是**规律**，不只适用于 Cloudflare。

### ⚠️ 踩坑 6：改完还是旧样子 → 先清缓存

**现象**：修改了路由或配置，刷新页面还是老样子，甚至还是 404。

**原因**：Cloudflare 为了加速，会把内容**缓存**在全球各地的节点上。你改的是源站，但访客访问到的是缓存。

**处理**：后台 → **Caching** → **Purge Everything**（清空所有缓存）。

**记这一句**：改完路由、域名、配置后"没生效"，**先清缓存，再怀疑代码**。

### ⚠️ 踩坑 7：本机好使、线上失败 → 检查绝对路径

**现象**：在你电脑上构建成功，云端构建失败，报 `EACCES`（权限错误）。

**原因**：我为了让构建在本机跑得更顺，写了一个**只有我电脑上才有的路径**：

```js
// ❌ 写死了我自己电脑的路径
vite: { cacheDir: '/home/vii/.tmp/vite-cache' }
```

云端服务器上根本没有这个文件夹，也没权限创建，于是失败。

**修复**：加上"环境判断"，让这段配置**只在你的电脑上生效**：

```js
import { existsSync } from 'node:fs';
const LOCAL_TMP = '/home/vii/.tmp';

export default defineConfig({
  vite: existsSync(LOCAL_TMP)
    ? { cacheDir: `${LOCAL_TMP}/vite-cache` }   // 本机走这个
    : {},                                        // 云端走默认设置
});
```

**记这一句**：任何"为了迁就我本机"的配置，**都要加环境判断**。写死绝对路径是云端构建失败的头号原因。

### ⚠️ 踩坑 8：本地图片好好的，上线后 404 → 检查上传规则

**现象**：本地开发时图片都正常，部署后有些图片加载不出来。

**原因**：我的 `.gitignore`（"哪些文件不用上传"的清单）里写了这一行：

```gitignore
motion/       # 本意是：忽略根目录的素材文件夹
```

但 Git 的规则是：**没加斜杠的目录名，会在任何层级匹配同名文件夹**。于是 `public/motion/segments/` 里的图片**也被一起忽略了**，没上传 → 线上就 404。

**修复**：开头加个斜杠，锁定"只忽略根目录那个"：

```gitignore
/motion/      # 只忽略仓库根目录下的 motion/
```

**这类问题最有欺骗性**——本地文件还在你硬盘上，页面当然正常；只有上线后才暴露。**记住**：网站第一次上线后，把所有图片、样式都点一遍，确认都在。

## 最后

这份教程里最有价值的不是那些配置怎么写——那些查官方文档都有。

真正花时间的是**文档不会告诉你的边界**：后台填的构建命令是写死的、命令行的权限是有限制的、网址匹配是严格的、`.gitignore` 的目录名会跨层级匹配、缓存会盖住你的修改。

它们都指向同一条经验：

**能明确写清楚的，就别依赖工具的"智能猜测"。**

![把乱成一团的线一根一根理直，每根尽头立好写清楚的牌子](/blog/cloudflare-personal-site-guide/06-write-it-clearly.webp)

工具的自动推断在简单场景下很舒服，但一旦碰到边界情况，它给出的报错信息往往**指向错误的方向**——你会去查代码，而问题其实在环境配置里。

这就是我这个站从零到上线，最实在的一条收获。
